# 요구사항 문서

## 소개

포트폴리오 웹사이트에 방문자가 개발자 문승규에 대한 정보를 실시간으로 질문하고 답변받을 수 있는 AI 챗봇 기능을 구현합니다. 이 챗봇은 채널톡과 유사한 UI/UX를 제공하며, Google Gemini 2.5 Flash-Lite 모델을 활용하여 자연스러운 대화형 인터페이스를 제공합니다.

## 용어 정의

- **챗봇\_시스템**: 사용자와 AI 간의 대화를 관리하는 전체 시스템
- **대화\_창**: 대화 내용을 표시하고 입력을 받는 UI 컴포넌트
- **챗봇\_버튼**: 챗봇 창을 열고 닫는 플로팅 버튼
- **메시지\_스트림**: AI로부터 실시간으로 전송되는 응답 텍스트
- **시스템\_프롬프트**: AI의 응답 스타일과 역할을 정의하는 초기 지시사항
- **채팅\_API**: 클라이언트와 AI 모델 간의 통신을 처리하는 서버 엔드포인트
- **제미나이\_모델**: Google의 Gemini 2.5 Flash-Lite AI 언어 모델
- **빠른*답변*버튼**: 사용자가 빠르게 선택할 수 있는 미리 정의된 질문 버튼
- **사용자\_핑거프린트**: IP 주소와 User Agent를 조합하여 생성한 사용자 고유 식별자
- **사용량\_제한**: 사용자가 일정 기간 내에 보낼 수 있는 최대 메시지 수
- **대화\_로그**: Supabase에 저장되는 사용자 질문과 AI 응답 기록
- **Supabase\_클라이언트**: Supabase 데이터베이스와 통신하는 클라이언트 라이브러리

## 요구사항

### 요구사항 1

**사용자 스토리:** 방문자로서, 포트폴리오 사이트에서 개발자에 대한 정보를 쉽게 물어볼 수 있도록 챗봇 버튼을 보고 싶습니다.

#### 수락 기준

1. 챗봇*시스템은 뷰포트의 우측 하단에 플로팅 챗봇*버튼을 표시해야 합니다
2. 사용자가 챗봇*버튼 위에 마우스를 올리면, 챗봇*시스템은 크기 조절 애니메이션 효과를 표시해야 합니다
3. 챗봇\_버튼은 64x64 픽셀 크기의 채팅 AI 아이콘 이미지를 표시해야 합니다
4. 챗봇\_버튼은 다른 페이지 콘텐츠 위에 표시되도록 z-index 30으로 고정되어야 합니다

### 요구사항 2

**사용자 스토리:** 방문자로서, 챗봇 버튼을 클릭하면 대화 창이 열려서 질문을 시작할 수 있기를 원합니다.

#### 수락 기준

1. 사용자가 챗봇*버튼을 클릭하면, 챗봇*시스템은 대화\_창을 열어야 합니다
2. 대화*창이 열려 있는 상태에서 사용자가 챗봇*버튼을 다시 클릭하면, 챗봇*시스템은 대화*창을 닫아야 합니다
3. 대화\_창은 뷰포트의 우측 하단 영역에 고정된 위치로 표시되어야 합니다
4. 대화\_창은 너비 320픽셀, 높이 500픽셀을 가져야 합니다
5. 대화\_창은 "AI 챗봇" 제목이 있는 헤더를 포함해야 합니다

### 요구사항 3

**사용자 스토리:** 방문자로서, 챗봇 창이 열리면 개발자에 대해 무엇을 물어볼 수 있는지 안내받고 싶습니다.

#### 수락 기준

1. 대화*창이 처음 열리면, 챗봇*시스템은 환영 메시지를 표시해야 합니다
2. 환영 메시지는 챗봇을 소개하고 목적을 설명해야 합니다
3. 챗봇*시스템은 미리 정의된 주제로 빠른*답변\_버튼을 표시해야 합니다: "나이", "취미", "사는 곳", "개발을 시작한 이유", "경력", "좋아하는 음식", "MBTI"
4. 사용자가 빠른*답변*버튼을 클릭하면, 챗봇\_시스템은 해당 질문을 사용자 메시지로 전송해야 합니다
5. 빠른*답변*버튼은 환영 메시지 아래에 표시되어야 합니다

### 요구사항 4

**사용자 스토리:** 방문자로서, 챗봇에 자유롭게 질문을 입력하고 전송할 수 있기를 원합니다.

#### 수락 기준

1. 대화\_창은 하단에 사용자 메시지를 위한 텍스트 입력 필드를 포함해야 합니다
2. 텍스트 입력 필드는 "메시지를 입력하세요..." 플레이스홀더 텍스트를 표시해야 합니다
3. 사용자가 입력 필드에 입력하면, 챗봇\_시스템은 전송 버튼을 활성화해야 합니다
4. 사용자가 전송 버튼을 클릭하면, 챗봇\_시스템은 메시지를 채팅\_API로 전송해야 합니다
5. 사용자가 입력 필드에서 Enter 키를 누르면, 챗봇\_시스템은 메시지를 채팅\_API로 전송해야 합니다
6. 메시지가 전송되면, 챗봇\_시스템은 입력 필드를 비워야 합니다

### 요구사항 5

**사용자 스토리:** 방문자로서, 내가 보낸 메시지와 AI의 응답을 대화 형식으로 보고 싶습니다.

#### 수락 기준

1. 대화\_창은 사용자 메시지를 구별되는 배경색으로 우측 정렬하여 표시해야 합니다
2. 대화\_창은 AI 메시지를 다른 배경색으로 좌측 정렬하여 표시해야 합니다
3. 새 메시지가 추가되면, 챗봇\_시스템은 메시지 목록의 하단으로 자동 스크롤해야 합니다
4. 챗봇\_시스템은 메시지를 위에서 아래로 시간순으로 표시해야 합니다
5. 대화\_창은 메시지 목록이 보이는 영역을 초과하면 스크롤바를 표시해야 합니다

### 요구사항 6

**사용자 스토리:** 방문자로서, AI가 응답을 생성하는 동안 실시간으로 텍스트가 나타나는 것을 보고 싶습니다.

#### 수락 기준

1. 채팅*API가 사용자 메시지를 받으면, 챗봇*시스템은 AI 응답을 실시간으로 스트리밍해야 합니다
2. 챗봇*시스템은 메시지*스트림의 각 토큰이 도착하는 대로 표시해야 합니다
3. AI가 응답을 생성하는 동안, 챗봇\_시스템은 입력 중 표시기를 표시해야 합니다
4. 메시지*스트림이 완료되면, 챗봇*시스템은 입력 중 표시기를 제거해야 합니다
5. 챗봇\_시스템은 스트리밍 오류를 우아하게 처리하고 사용자에게 오류 메시지를 표시해야 합니다

### 요구사항 7

**사용자 스토리:** 방문자로서, AI가 개발자의 실제 정보를 기반으로 정확하게 답변하기를 원합니다.

#### 수락 기준

1. 채팅*API는 prompts/systemProfilePrompt.md 파일에서 시스템*프롬프트를 로드해야 합니다
2. 채팅*API는 제미나이*모델에 대한 모든 요청에 시스템\_프롬프트를 포함해야 합니다
3. 제미나이*모델은 시스템*프롬프트를 사용하여 개발자의 프로필과 일치하는 응답을 생성해야 합니다
4. 챗봇\_시스템은 채팅\_API로 전송하기 전에 사용자 입력을 `<user_input>` 태그로 감싸야 합니다
5. 채팅\_API는 모든 응답에 Gemini 2.5 Flash-Lite 모델을 사용해야 합니다

### 요구사항 8

**사용자 스토리:** 방문자로서, 챗봇이 빠르게 응답하고 부드럽게 작동하기를 원합니다.

#### 수락 기준

1. 채팅\_API는 정상적인 네트워크 조건에서 30초 이내에 사용자 메시지에 응답해야 합니다
2. 챗봇\_시스템은 효율적인 상태 관리를 위해 @ai-sdk/react의 useChat 훅을 사용해야 합니다
3. 대화\_창은 초당 60프레임으로 애니메이션을 부드럽게 렌더링해야 합니다
4. 챗봇*시스템은 반복적인 파일 읽기를 피하기 위해 시스템*프롬프트를 캐시해야 합니다
5. 대화*창이 닫히면, 챗봇*시스템은 대화 기록을 보존해야 합니다

### 요구사항 9

**사용자 스토리:** 방문자로서, 챗봇이 다양한 화면 크기에서 작동하기를 원합니다.

#### 수락 기준

1. 챗봇\_버튼은 마우스 상호작용에 적합한 호버 효과를 사용해야 합니다
2. 챗봇\_시스템은 모바일 전용 터치 제스처를 구현하지 않아야 합니다
3. 대화\_창은 320x500 픽셀의 고정 크기를 유지해야 합니다
4. 챗봇\_시스템은 적절한 글꼴 크기와 간격을 사용해야 합니다
5. 대화\_창은 화면 크기에 관계없이 우측 하단에 고정되어야 합니다

### 요구사항 10

**사용자 스토리:** 방문자로서, 챗봇 UI가 채널톡과 유사한 친숙한 디자인을 가지기를 원합니다.

#### 수락 기준

1. 대화\_창은 채널톡 디자인과 유사한 헤더 바를 가져야 합니다
2. 챗봇\_버튼은 그림자 효과가 있는 원형이어야 합니다
3. 대화\_창은 깊이감을 위해 둥근 모서리와 그림자를 가져야 합니다
4. 메시지 말풍선은 둥근 모서리와 적절한 패딩을 가져야 합니다
5. 대화\_창은 포트폴리오 웹사이트의 전체 디자인과 조화를 이루는 색상 구성을 사용해야 합니다

### 요구사항 11

**사용자 스토리:** 방문자로서, 챗봇 남용을 방지하기 위해 일정 횟수 이상 질문할 수 없도록 제한되기를 원합니다.

#### 수락 기준

1. 채팅\_API는 사용자의 IP 주소와 User Agent를 조합하여 사용자\_핑거프린트를 생성해야 합니다
2. 채팅\_API는 사용자\_핑거프린트를 SHA-256 해시로 암호화해야 합니다
3. 챗봇\_시스템은 사용자당 최대 3개의 메시지로 사용량\_제한을 적용해야 합니다
4. 사용자가 사용량\_제한에 도달하면, 챗봇\_시스템은 "오늘의 질문 횟수를 모두 사용했습니다. 내일 다시 방문해주세요!" 메시지를 표시해야 합니다
5. 사용량\_제한에 도달하면, 챗봇\_시스템은 메시지 입력 필드를 비활성화해야 합니다
6. 챗봇\_시스템은 사용량\_제한을 24시간마다 리셋해야 합니다
7. 채팅\_API는 메시지를 처리하기 전에 Supabase에서 사용자의 현재 사용량을 확인해야 합니다

### 요구사항 12

**사용자 스토리:** 개발자로서, 방문자들이 어떤 질문을 하고 어떤 응답을 받았는지 분석하기 위해 대화 내용을 저장하고 싶습니다.

#### 수락 기준

1. 채팅\_API는 사용자 질문과 AI 응답을 하나의 대화 쌍으로 Supabase의 대화\_로그 테이블에 저장해야 합니다
2. 대화\_로그는 사용자\_핑거프린트, 사용자 질문, AI 응답, 타임스탬프를 포함해야 합니다
3. 채팅\_API는 AI 응답이 완료된 후 대화 쌍을 저장해야 합니다
4. 채팅\_API는 Supabase\_클라이언트를 사용하여 데이터베이스와 통신해야 합니다
5. 데이터 저장 실패 시, 챗봇\_시스템은 여전히 AI 응답을 사용자에게 표시해야 합니다
6. 채팅\_API는 환경 변수에서 Supabase URL과 API 키를 로드해야 합니다
7. 대화\_로그 테이블은 사용자\_핑거프린트 필드에 인덱스를 가져야 합니다
8. 대화\_로그 테이블은 user_question과 ai_response 컬럼을 가져야 합니다

### 요구사항 13

**사용자 스토리:** 방문자로서, 남은 질문 횟수를 알고 싶습니다.

#### 수락 기준

1. 대화\_창은 헤더 또는 입력 필드 근처에 남은 질문 횟수를 표시해야 합니다
2. 챗봇\_시스템은 메시지를 보낼 때마다 남은 횟수를 업데이트해야 합니다
3. 남은 횟수가 0이 되면, 챗봇\_시스템은 경고 스타일로 표시해야 합니다
4. 채팅\_API는 응답에 현재 사용량과 남은 횟수 정보를 포함해야 합니다
5. 챗봇\_시스템은 대화\_창이 열릴 때 현재 사용량을 확인해야 합니다
